\section{Benchmark Dataset Construction}
\label{sec:dataset}

To evaluate chunking strategies on realistic technical software corpora, we construct a dedicated evaluation benchmark based on the official Angular documentation \citep{angular2024docs}.

\subsection{Corpus and Preprocessing}
The source corpus consists of 384 Markdown documents extracted from the official Angular core documentation repository. 
Each document exhibits authentic developer-facing structural patterns:
\begin{itemize}
    \item \textbf{Syntactic Components:} Markdown headers (\texttt{\#}, \texttt{\#\#}, \texttt{\#\#\#}, \texttt{\#\#\#\#}), YAML frontmatter metadata, TypeScript/HTML fenced code listings, bulleted itemizations, and custom callout blocks (\texttt{NOTE}, \texttt{HELPFUL}, \texttt{CRITICAL}).
    \item \textbf{Preprocessing Pipeline:} Frontmatter metadata is normalized into structured attributes. Embedded raw HTML tags are sanitized, while relative asset links are canonicalized. Document heading trees are parsed into hierarchical symbol paths.
\end{itemize}

\subsection{Benchmark Construction and Expert Review}
We followed a rigorous human-in-the-loop curation workflow:
\begin{enumerate}
    \item \textbf{LLM-Assisted Generation:} Candidate question-answer pairs and candidate evidence spans were drafted by querying ChatGPT (\texttt{gpt-4o}) with source document sections.
    \item \textbf{Sequential Expert Review:} Three professional software engineers specializing in Angular and web architecture reviewed each candidate record sequentially. Reviewers verified API accuracy, verified evidence boundaries, and refined question phrasing to reflect authentic developer search intents.
    \item \textbf{Decoupled Ground Truth Principle:} A core methodological design requirement was that \textit{ground-truth evidence spans must never be tied to specific chunk IDs}. Instead, evidence is recorded as raw character offsets, section headings, and exact text spans within the source document. This ensures absolute neutrality when evaluating arbitrary chunking strategies.
\end{enumerate}

\subsection{Dataset Statistics and Difficulty Stratification}
The finalized benchmark comprises 140 QA records grounded in 233 distinct evidence items. We stratify queries into three difficulty levels based on structural scope:
\begin{itemize}
    \item \textbf{Easy (60 queries):} Single-section retrieval. The required evidence resides entirely within a single localized subsection or code block.
    \item \textbf{Medium (40 queries):} Cross-section retrieval. Answering the query requires synthesizing evidence from two or more distinct sections within the same document.
    \item \textbf{Hard (40 queries):} Cross-document retrieval. Grounding requires identifying and aggregating evidence spans distributed across distinct documentation files.
\end{itemize}
