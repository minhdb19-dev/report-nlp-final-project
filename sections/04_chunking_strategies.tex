\section{Chunking Strategies}
\label{sec:chunking_strategies}

We implement and evaluate three distinct document chunking strategies representing baseline token-counting, deterministic AST parsing, and hybrid LLM-guided segmentation.

\subsection{Fixed-Size Chunking (Baseline)}
The fixed-size strategy represents the industry standard:
\begin{itemize}
    \item \textbf{Token Window:} Uses a uniform sliding window of 512 tokens with a static 64-token overlap stride ($12.5\%$ overlap ratio) using the \texttt{cl100k\_base} tokenizer.
    \item \textbf{Syntactic Obliviousness:} Chunks are formed purely by token counts without inspecting Markdown delimiters, frequently bisecting code blocks, bullet lists, or inline callout admonitions.
\end{itemize}

\subsection{Structure-Aware Chunking (AST-Based)}
Our structure-aware chunking strategy leverages an Abstract Syntax Tree (AST) parser to strictly honor document syntax:
\begin{itemize}
    \item \textbf{Heading Hierarchy:} Each chunk maintains its ancestral heading path as an embedded metadata prefix (e.g., \texttt{\# Router > \#\# Guards > \#\#\# CanMatch}).
    \item \textbf{Non-Coalescing Sibling Constraint:} Sibling sections at the same hierarchy level are never coalesced into a single chunk, even if their combined token count falls below 512 tokens, preserving strict thematic isolation.
    \item \textbf{Atomic Block Preservation:} Fenced code listings, tables, and callouts are treated as indivisible blocks. Content is partitioned strictly along natural block boundaries.
\end{itemize}

\subsection{Prompt-Based Chunking (LLM with Local Verification)}
The prompt-based chunking strategy utilizes an LLM to propose semantic block boundaries, backed by deterministic local validation:
\begin{itemize}
    \item \textbf{LLM Boundary Proposal:} An instruction-tuned LLM receives Markdown documents and outputs proposed semantic segment boundaries.
    \item \textbf{Local Code Invariant Checks:} To guarantee reliability, a local post-processing verification engine enforces four strict invariants:
    \begin{enumerate}
        \item \textit{Coverage:} Every character of the source text must appear in exactly one chunk (no omitted text).
        \item \textit{Order:} Chunk sequence must strictly match the original document flow.
        \item \textit{Provenance:} Chunks must contain verbatim source text without hallucinated or rephrased content.
        \item \textit{Token Bounds:} Chunks exceeding maximum token limits are recursively subdivided along AST boundaries.
    \end{enumerate}
\end{itemize}

\subsection{Bridge to Experimental Pipeline: Generated Artifacts}
\label{sec:artifacts_bridge}
The three chunking strategies produce standardized, self-contained JSON artifact files:
\begin{itemize}
    \item \texttt{fixed\_size\_v1.json}: Index of uniform 512-token chunks with fixed stride.
    \item \texttt{structure\_aware\_v1.json}: Index of AST-delimited chunks containing full breadcrumb metadata.
    \item \texttt{prompt\_based\_v1.json}: Historical artifact containing LLM-proposed and locally verified semantic chunks.
\end{itemize}
These standardized artifacts serve as the unified input interface for the subsequent experimental pipeline detailed in Chapter~\ref{sec:experimental_setup}.
